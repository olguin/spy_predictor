The fresh Pi session per authorized action is an implementation choice, not a
departure from the cooperative model/tool loop: the controller persists history
and tool results between intentional model turns. Its latency and token cost
still need measurement. Sequential execution is below the two-worker ceiling.

The next phase is **M0 acceptance preparation and M1 completion**, not M2. This
keeps the original first-slice order and fixes shortcomings rather than relaxing
the plan to match existing code. Detailed completion evidence will be appended
after implementation and validation; items are not marked passed in advance.

## Continuation result

M0 has concrete disjoint development/release source-input mandates with frozen
hashes, credential-free capability checks with actual primary-source access, and
a hashed linkage to pre-change comparator outputs. The release inputs remain
unevaluated; their mere existence is not release acceptance.

The identified M1 drift was corrected in prompts v1.1/v1.2 and versioned runtime
policies: initial findings are isolated; feed/SEC discovery and normalized data
reuse existing parsers; task manifests match visible evidence; Director triage
governs follow-ups; review can trigger bounded specialist research; completed
answers can be reused explicitly; original objection/question identities are
required on the final wire; and each task has a fixed turn ceiling. Rejected
submissions may use remaining turns for explicit, receipted correction. A role
returning to another role is allowed when it creates a new acyclic task dependency;
duplicate requests and the shared round limit prevent unbounded cycling.

Live testing found and retained two rejected candidates: v2 omitted original
objection dispositions at final acceptance, and v3 contradicted its critical gaps
with a `watch` assessment. Neither artifact was rewritten or accepted retroactively.
The separately registered v4 run completed all ten tasks, including Macro→Company
answer reuse and challenge-triggered Company follow-up. Its final draft explains
both question effects and every original objection. Structural checks and a
scoped final-claim review passed. This establishes **M1 engineering acceptance**,
not calibrated predictions, superiority of cooperation, or M4 usefulness.

repair long-filing excerpts, then add the remaining roles and multi-symbol/ETF
workflows. Define canonical observable conditions and fixed benchmark context
before presenting price-sensitive guidance. Carry forward the current exact
identity transport, independent task inputs and budget bounds. The five-symbol
acceptance must produce differentiated, evidence-supported theses with explicit
omissions; a missing optional source must not force a generic answer everywhere.

M3's final refresh, immutable publication, review/feedback and corporate-action-safe
post-publication observation origin remain mandatory. M4 still needs independent
release-case comparisons of the old pipeline, single agent and cooperating system,
actual resource accounting, defect review and user usefulness feedback. None of
these requirements was removed to make the current implementation appear complete.


## M2 continuation and explicit M3 addition

At the user's instruction, M2 now extends the existing controller with grouped
five-symbol tasks, the remaining roles, scoped per-instrument findings, ETF
look-through, deterministic scenario valuation/comparisons, canonical conditions
and a frozen market-context universe. Versioned contracts preserve the original
single-company artifacts and independent Challenger/follow-up rules. Sequential
execution stays within the two-worker ceiling; the global budget is not multiplied
by instrument count. Optional source failures remain gaps and critical dependencies
block only their declared instruments. Full acceptance evidence is maintained in
the implementation record; a scripted five-symbol test is not represented as a
live-model quality evaluation.

Bounded live candidates are retained with their actual incomplete outcomes,
including worker-boundary, input-budget and schema-validation failures. Follow-on
versions reduce duplicate context, preserve receipts and narrow inapplicable wire
fields, with the same model and aggregate limits. The implementation record
identifies every candidate and its measured resource use. This is measured development,
not an equal-cost M4 comparison or a release-case evaluation.

The only requested scope addition is the M3 graphical single-run monitor. The
[design contract](AGENTIC_INVESTMENT_RUN_MONITOR.md) chooses a role-grouped task
timeline, selectable request/dependency links, explicit time/budget ceilings and
an individual findings/evidence/trace inspector. It must replay recorded events,
show uncertainty honestly and remain a local read-only view. M3's publication
refresh, immutable versions and corporate-action-safe publication-origin contract
and M4's comparison/user-usefulness gates remain unchanged and required.
